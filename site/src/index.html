For teams that build agent harnesses and frameworks

Find the request that broke your prompt cache.

One reordered tool list, or a timestamp in the system prompt, and every later request pays full price. Nothing reports it. prefixlens names the call, the block that changed, what it cost and the fix, and fails the test in CI before it reaches the bill.

Open source, MIT, version {{version}}. No account, no telemetry, no runtime dependencies. Reads Anthropic Messages, OpenAI Chat Completions and OpenAI Responses requests, from your own harness or through a framework.

The same session, as a CI step

The check fails for what your code did: a changed tool list, system prompt, history, model or cache-relevant parameter, or a prefix that changed without being declared.

It passes what your code did not do: cache expiry, a miss on the provider's side, a first call, and a break you declared, such as a compaction.

Hand it to your agent

Paste these instructions into the coding agent that works in your harness's repository. It reads how your requests are built, adds the matching test with your real system prompt, tools and memory settings, runs it, and tells you about any cache break it finds. It asks before it changes your own code, your CI or your repository's layout.

  1. Reads how your harness sends a conversation: in full or kept by the provider, what trims it, and everything that can change a request mid-session.
  2. Finds whether you build the request yourself or a framework does, and whether the code is JavaScript at all.
  3. Adds prefixlens as a dev dependency.
  4. Writes the test in your own test runner, beside your other tests.
  5. Runs it. A failure is a real cache break: it shows you the message and a fix, and applies the fix only when you say so.
  6. Checks that your CI picks the test up, and commits or pushes nothing unless you ask.

The test makes no network call and needs no API key: a stand-in answers every model call. Read the instructions before you paste them. They are all here, and the same text is at /agent.md.

What it tells apart

Fails Your harness changed its own prefix

  • The tool list gained, lost or reordered a tool, or a definition changed.
  • The system prompt was edited, or carries a clock, an id or a relative date that is rendered again on each call.
  • History was rewritten: a message edited, inserted, removed or reordered, tool output rendered again, a window that slides, a rewind.
  • The model or a parameter that is part of the cached prefix changed.
  • A prefix changed with nothing cached yet: a break waiting for a cache to hit.

Passes Not something your code did

  • Expiry: the prefix was intact and the cache entry had run out.
  • The provider's side: the prefix was intact and in time, and the provider read nothing.
  • A first call, cold or warm.
  • A declared break: a compaction, a revert or a settings change your harness says it meant, counted with its cost, apart from the rest.

What it does not do

  • It sees the request your code sends, not what the provider does with it. Eviction and routing show up as a miss with the prefix intact.
  • Costs are list prices from a bundled table, not your bill. Discounts, batch tiers and subscriptions are not applied.
  • The test helpers are JavaScript and TypeScript. From another language, your tests write the request bodies to a file and one command checks them, as the instructions above set up, or you record through the proxy, or write the trace format.
  • Gemini's native API and WebSocket transports are not recorded.
  • It is before 1.0: the JSON output may change in a minor version.
