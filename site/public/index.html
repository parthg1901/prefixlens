For teams that build agent harnesses and frameworks

Find the request that broke your prompt cache.

One reordered tool list, or a timestamp in the system prompt, and every later request pays full price. Nothing reports it. prefixlens names the call, the block that changed, what it cost and the fix, and fails the test in CI before it reaches the bill.

Open source, MIT, version 0.7.0. No account, no telemetry, no runtime dependencies. Reads Anthropic Messages, OpenAI Chat Completions and OpenAI Responses requests, from your own harness or through a framework.

The same session, as a CI step

The check fails for what your code did: a changed tool list, system prompt, history, model or cache-relevant parameter, or a prefix that changed without being declared.

It passes what your code did not do: cache expiry, a miss on the provider's side, a first call, and a break you declared, such as a compaction.

Hand it to your agent

Paste these instructions into the coding agent that works in your harness's repository. It reads how your requests are built, adds the matching test with your real system prompt, tools and memory settings, runs it, and tells you about any cache break it finds. It asks before it changes your own code, your CI or your repository's layout.

  1. Reads how your harness sends a conversation: in full or kept by the provider, what trims it, and everything that can change a request mid-session.
  2. Finds whether you build the request yourself or a framework does, and whether the code is JavaScript at all.
  3. Adds prefixlens as a dev dependency.
  4. Writes the test in your own test runner, beside your other tests.
  5. Runs it. A failure is a real cache break: it shows you the message and a fix, and applies the fix only when you say so.
  6. Checks that your CI picks the test up, and commits or pushes nothing unless you ask.

The test makes no network call and needs no API key: a stand-in answers every model call. Read the instructions before you paste them. They are all here, and the same text is at /agent.md.

agent.md
# Add a prompt-cache regression test with prefixlens

This repository sends requests to an LLM API, directly or through a framework. Add a test that fails when a code change breaks the provider's prompt cache. Use prefixlens: the npm package `prefixlens`, at exactly version 0.7.0 (https://github.com/parthg1901/prefixlens).

Why it matters: a provider caches the start of a request. When anything early in the request differs from the previous call of the same conversation (the tool list or its order, the system prompt, an earlier message), everything after that point is billed at full price, and nothing reports it. prefixlens compares consecutive requests and names the first block that changed.

## 1. Understand the harness

Before you write anything, read the code that builds and sends model requests, and find out:

- **Where the conversation lives.** Is it sent in full with every request, or does the provider keep it (Anthropic's `thread`, OpenAI's `previous_response_id` or `conversation`)?
- **What trims it.** A history window, a compaction, a token limit.
- **What can change a request during a session.** Find every such thing this harness has, not a sample of them: reminders, memory and reloaded instructions are only the common ones.
- **Where cache breakpoints are set**, if the code sets any (`cache_control`, a cache key).

Write what you found in a few lines; they open your report. The list of what can change a request is what the test has to cover.

When the provider keeps the conversation, a request carries only what is new. Consecutive requests are then not meant to extend each other, and prefixlens cannot judge them. Test the path that sends the conversation in full, if the harness has a setting for it, and say in your report that the path the provider keeps is not covered. With no such setting, stop and say so.

## 2. Decide which case this is

- **Case A: the project builds the request body itself.** There is a function that returns the body for the Anthropic Messages, OpenAI Chat Completions or OpenAI Responses API.
- **Case B: a framework or an SDK builds it.** The Vercel AI SDK, Mastra, LangChain, or a provider's SDK called from an agent loop.
- **Case C: the project is not JavaScript or TypeScript.** The test helpers are JavaScript, so the project's own tests capture the request bodies and a small Node script checks them.

When A and B are both true, do case B on the main agent loop: it covers more.

## 3. Install

Add `prefixlens` as a dev dependency at exactly version 0.7.0, with the package manager the project already uses (for example `npm install --save-dev --save-exact prefixlens@0.7.0`), and keep the lockfile change. It needs Node.js 22 or later, or Bun, and has no dependencies of its own. In case C nothing is installed: step 4 runs prefixlens with `npx` at that exact version.

## 4. Write the test

Use the project's own test runner and put the test beside its other tests. Build the agent the way production does: the real system prompt, tools, memory and history settings. A simplified copy protects nothing. Exercise everything from step 1 that can change a request; what one conversation cannot hold goes in a second one. Writing the test should not need a change to the project's own code.

Case A, two consecutive requests of one conversation:

```ts
import { assertPrefixStable } from "prefixlens/test"

const first = buildRequest(conversation)                    // the project's own request builder
const second = buildRequest([...conversation, ...nextStep])  // the same conversation, one step later
assertPrefixStable(first, second)
```

Cover a second user turn, a tool call with its result, and anything the project adds during a session (reminders, memory, changed instructions).

Case B, a whole run with a stand-in provider:

```ts
import { callTools, recordRequests } from "prefixlens/test"

// The session answers every model call itself: no network, no API key, no cost.
const session = recordRequests({ reply: callTools([{ name: "<one of the agent's tools>", args: {} }]) })
// Hand session.fetch to the model provider the agent uses. Take the first of these that applies:
//   1. The code already accepts a fetch function or a client: pass it.
//        createAnthropic({ apiKey: "test", fetch: session.fetch })      Vercel AI SDK, Mastra
//        new OpenAI({ apiKey: "test", fetch: session.fetch })           a provider's SDK
//   2. It does not: replace the global fetch for this test only. Set it and the provider's API key
//      variable ("test") before the agent's module is imported, and put the real fetch back afterwards.
//        globalThis.fetch = session.fetch
//   3. Neither works: stop and ask before changing the project's code (see Rules).
// Then run the real agent in one conversation for at least eight user turns,
// so that a history window or a compaction, if there is one, is reached.
// Name each thing the test does before it does it, one name for each item of your step 1 list:
session.step("first question")
// ... the agent's turn ...
session.step("reload instructions")
// ... the change, then the agent's turn ...
session.assertStable()
```

A failure then names the step, and one run reports every step that broke. `session.summary().text` is the same result as a table, one row for each step.

Case C, request bodies captured by the project's own tests. Nothing is added to the repository, but the test now needs Node.js 22 or later where it runs: tell the user, and ask before making the tests depend on it.

1. In the project's test runner, write a test that collects the JSON bodies of consecutive model requests of one conversation, in the order they are sent and exactly as they go to the provider. Either call the project's request builder for each step, as in case A, or run the agent against the fake provider or the HTTP mock its tests already use and capture each body, as in case B, for at least eight user turns.
2. In the test, write the bodies to a temporary file, as one JSON array or one body on each line, and run:

```
npx --yes prefixlens@0.7.0 check --requests <file>
```

3. Fail the test when the command exits with anything but 0, showing what it printed. That output is prefixlens's message. It exits 1 for a cache break and 2 when the bodies could not be checked.

When the tests cannot produce request bodies without a real provider, stop and tell the user. The other route records a real run through a local proxy (`npx prefixlens record`, then `npx prefixlens check` on the trace); it makes real model calls, so set it up only when the user asks for it.

## 5. Run it

- **It passes.** Go to step 6.
- **It fails.** The message names the step and the call, the first changed block, about how many tokens the break re-reads and what that costs at list prices, a diff and a fix. Almost always that is a real cache break in this project, not a problem with the test: do not loosen the test, shorten the run or change the agent's settings to make it pass. When what you learned in step 1 says the change cannot cost a cache read, do not allow it on your own either: show the user the message and your reasoning.
  - When the fix looks small (a timestamp or an id in the system prompt, tools sent in an unstable order), show it to the user as a diff and ask before applying it. Keep what the model needs: fix a value once per session or send it in a new message, and delete it only when nothing uses it. When the user has already told you to apply fixes, make it, in a commit of its own if you are committing, and say what you changed.
  - When the break is deliberate (a compaction, a history window the team chose), stop and show the user the message. If they confirm it, allow it in that step only: `session.assertStable({ allowBreakIn: { compaction: "compaction" } })` allows one break in the step named "compaction". Where the run has no steps, allow it at that call: `allowBreakAt: { 7: "compaction" }`, or `--allow-break-at 7=compaction` in case C. The number is the call's number in the failure message; calls are counted from 1.
  - Otherwise stop and show the user the message.
  - Leave the failing test in place, and say that it fails and why.

## 6. Make sure CI runs it

Check that the command CI already runs picks the new test up. When the project has no workflow that runs tests, say so and ask before adding one. In case C, CI also needs Node.js 22 or later, and `npx` downloads the package the first time it runs: tell the user, and change a workflow only when they agree.

## 7. Report

Start with what you found in step 1. Then say which case it was, the files you added or changed, the test's output with the summary table when the test has steps, any cache break you found with prefixlens's message for it and the size it gives, anything you are waiting for an answer on, and what the test does not cover: name each thing from step 1 that it leaves out, and why.

## Rules

- Send no real model requests and use no real API key.
- Ask before changing the project's own code. That covers any fix from step 5, and any change made only so that a test can reach the model provider. Show the change as a diff first, and keep it as small as it can be.
- Ask before adding a CI workflow, or making the tests need Node.js in case C.
- When there is nobody to ask, stop at that point and put the question in your report.
- Install exactly version 0.7.0, and keep the lockfile change.
- Commit no trace files: a trace holds prompts.
- In your report, quote only the lines prefixlens names; don't paste full system prompts or anything that looks like a secret.
- Do not commit, push or open a pull request unless the user asks you to.
- More detail, when you need it: https://github.com/parthg1901/prefixlens/blob/main/docs/assertions.md

Or wire it yourself

Three ways in, by where your request is built. Each of these was run before it was put here.

Your harness has a function that builds the request body. Build it for two consecutive steps of one conversation and assert that the second keeps the first one's prefix.

test/prefix.test.ts
import { test } from "node:test"                  // or bun:test, vitest, jest
import { assertPrefixStable } from "prefixlens/test"
import { buildRequest } from "../src/request.ts"  // your harness's own request builder

test("a new step extends the previous request", () => {
  const history = [{ role: "user", content: "Fix the failing test." }]
  const first = buildRequest(history)
  const second = buildRequest([...history, { role: "assistant", content: "Reading it now." }, { role: "user", content: "Go on." }])

  // Nothing is sent to a provider: two request bodies are compared.
  assertPrefixStable(first, second)
})

The request is built inside the SDK, so give its provider a session's fetch. The session answers every model call itself and compares each request with the one before it in the same conversation. Run with ai 7 and @ai-sdk/anthropic 4.

test/prefix.test.ts
import { createAnthropic } from "@ai-sdk/anthropic"
import { generateText, stepCountIs, tool, type ModelMessage } from "ai"
import { test } from "node:test"                  // or bun:test, vitest, jest
import { callTools, recordRequests } from "prefixlens/test"
import { z } from "zod"

test("the agent keeps its prefix across turns and tool calls", async () => {
  // The session stands in for the provider: after each user message the model calls read_file once, then answers.
  const session = recordRequests({ reply: callTools([{ name: "read_file", args: { path: "src/app.ts" } }], "Done.") })
  const model = createAnthropic({ apiKey: "test", fetch: session.fetch })("claude-sonnet-5-5")
  const tools = {
    read_file: tool({ description: "Read a file.", inputSchema: z.object({ path: z.string() }), execute: async () => "export const app = 1" }),
  }

  // Your agent loop goes here. This one keeps one history and sends all of it.
  const messages: ModelMessage[] = []
  for (const question of ["Where is the bug?", "Fix it.", "Add a test."]) {
    messages.push({ role: "user", content: question })
    const result = await generateText({ model, system: "You are a coding agent.", tools, messages, stopWhen: stepCountIs(5) })
    messages.push(...result.responseMessages)
  }

  session.assertStable()
})

The same session, given to the model of a Mastra agent with memory. Run with @mastra/core 1.83 and @mastra/memory 1.41.

test/prefix.test.ts
import { createAnthropic } from "@ai-sdk/anthropic"
import { Agent } from "@mastra/core/agent"
import { LibSQLStore } from "@mastra/libsql"
import { Memory } from "@mastra/memory"
import { test } from "node:test"                  // or bun:test, vitest, jest
import { recordRequests } from "prefixlens/test"

test("the agent keeps its prefix through a long thread", async () => {
  const session = recordRequests()
  const model = createAnthropic({ apiKey: "test", fetch: session.fetch })("claude-sonnet-5-5")
  const agent = new Agent({
    id: "support",
    name: "support",
    instructions: "You are a support agent.",
    model,
    memory: new Memory({ storage: new LibSQLStore({ id: "test", url: ":memory:" }) }),
  })

  // Long enough to pass any history window: 8 questions are 16 stored messages.
  for (let turn = 1; turn <= 8; turn++) {
    await agent.generate(`Question ${turn}`, { memory: { thread: "thread-1", resource: "user-1" } })
  }

  session.assertStable()
})

With Mastra's default memory this test fails at the seventh call. The default keeps the last ten messages, so from then on the oldest ones leave on every request:

the test's output
PrefixBreakError: prefix not stable at call 7 (lane main, compared with call 6): 2 oldest messages removed from the start of history (9 kept, 2 appended)

  first changed block: 2 of 12 (message #1, user); block 1 still matches, everything from block 2 on is re-read

  fix: a window that slides on every call re-reads the whole history each time: drop history in chunks at a saved boundary (cut rarely, and replay from the same cut until the next one), or keep history append-only.
  if this change is intentional, pass { allowBreakAt: { 7: { reason: "..." } } }

  1 more call changes the prefix: call 8 (2 oldest messages removed from the start of history (9 kept, 2 appended))

This is a trade-off Mastra documents, not a bug: its docs point long threads to observational memory, which keeps the prefix stable. The test shows you the call where a setting starts to cost you, whichever you choose.

No test to write, and it works for a harness in any language. Record a real run through a local proxy, then read the report or gate on it. The proxy forwards your credentials and never writes them.

terminal
# 1. Record: a local proxy forwards every request unchanged and writes one record per model call.
npx prefixlens record --provider anthropic -o run.trace.jsonl     # or --provider openai

# 2. Point your agent at it and run a task as usual, in any language.
export ANTHROPIC_BASE_URL=http://127.0.0.1:8787                   # openai: OPENAI_BASE_URL=http://127.0.0.1:8787/v1

# 3. Read it, or gate on it.
npx prefixlens report run.trace.jsonl --html    # every call: tokens read, written and lost, and the cause of each miss
npx prefixlens check run.trace.jsonl            # exits 1 when your harness broke its own cache

Read a report

For every call: the tokens read from the cache, written and lost, the hit rate and the cost. For every miss: the first changed block, a diff and what it cost. This is the report of the session at the top of the page, exactly as prefixlens report --html writes it: one file, nothing loaded from elsewhere.

What it tells apart

Fails Your harness changed its own prefix

  • The tool list gained, lost or reordered a tool, or a definition changed.
  • The system prompt was edited, or carries a clock, an id or a relative date that is rendered again on each call.
  • History was rewritten: a message edited, inserted, removed or reordered, tool output rendered again, a window that slides, a rewind.
  • The model or a parameter that is part of the cached prefix changed.
  • A prefix changed with nothing cached yet: a break waiting for a cache to hit.

Passes Not something your code did

  • Expiry: the prefix was intact and the cache entry had run out.
  • The provider's side: the prefix was intact and in time, and the provider read nothing.
  • A first call, cold or warm.
  • A declared break: a compaction, a revert or a settings change your harness says it meant, counted with its cost, apart from the rest.

What it does not do

  • It sees the request your code sends, not what the provider does with it. Eviction and routing show up as a miss with the prefix intact.
  • Costs are list prices from a bundled table, not your bill. Discounts, batch tiers and subscriptions are not applied.
  • The test helpers are JavaScript and TypeScript. From another language, your tests write the request bodies to a file and one command checks them, as the instructions above set up, or you record through the proxy, or write the trace format.
  • Gemini's native API and WebSocket transports are not recorded.
  • It is before 1.0: the JSON output may change in a minor version.
